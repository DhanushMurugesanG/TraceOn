# User feedback — 2026-05-26

Verbatim feedback from the same user whose first-run experience is
captured in [first-run-experience.md](first-run-experience.md), after a
second session that exercised TraceOn on top of the v0.0.5 + v0.0.6
fixes. Preserved as written so the rough edges and the "is it worth it"
read both stay visible.

For each drag-point, the corresponding fix/scope is tracked in
[../packages/mcp](../packages/mcp) issues / commits as it ships — see

## Where it earned its keep, concretely

Two moments stood out and neither would have been delivered by plain
Playwright:

**The CORS-`traceparent` surfacing.** When the cycle save was silently
dying mid-test, the test-level signal was just
`expect(toast visible) timed out`. Tier 2 had the actual cause spelled
out — _"Request header field `traceparent` is not allowed by
Access-Control-Allow-Headers in preflight response."_ I would not have
guessed `traceparent` injection was the differentiator from a
screenshot. One read of the evidence packet collapsed what would have
been an hour of devtools poking.

**Today's update bug.** Same pattern at a smaller scale — when I
extended the test for resume + update, the Tier 1 / Tier 2 split helped
me look at the right thing first.

The unifying theme: TraceOn is worth it specifically when **the failure
surface lies about the cause** — the user sees one symptom (toast
missing, page blank) but the actual issue is several layers down
(CORS, federation load, JSON unmarshal). For that class of bug, it's
the cheapest path to the truth I've used.

## Where it dragged — and these are real

### First-run friction is brutal

Three separate blocking issues before I got a useful trace:

- `pnpm-install` errored on `ERR_PNPM_IGNORED_BUILDS: esbuild` because
  the runner shells out to `pnpm exec`
- `traceparent` not allowed by your backend CORS — needed a one-line
  backend edit
- `webServer` config pointing at port 5173 hanging 2 minutes before
  timing out

None of these are TraceOn bugs; they're "the environment isn't set up
for trace injection." But each was a full iteration of trial-and-error.
A pre-flight check at the start of a run ("we're injecting `traceparent`
— your backends at X need to allow it; pnpm install will run, allow
esbuild builds first") would save a fresh user a long time.

### `env` parameter doesn't forward to the test process

I passed `env="AUTH_TOKEN=..."` to `traceon_verify`, the schema accepted
it, and the Playwright subprocess never saw it. Had to inline the JWT
in the test file every iteration — strip before commit, re-inline next
round, repeat. Either document that `env` doesn't forward, or fix it
to pass through as actual process env.

### Coverage attribution warnings are noise more often than signal

Every passing run flagged "backend file with no spans — change may not
be exercised" for my changed files, even though the test asserted on
real backend-driven DOM that could only have come from those code
paths. The OpenTelemetry attribution gap is known per the skill docs,
but the warning still shows up identically whether it's a real miss or
an attribution false alarm. Hard to trust over time.

### Generic failure summaries swallow the real cause

The `webServer`-timeout run returned `name: "unknown"`,
`steps_executed: []`, `failure_message: ""` — I had to read the raw
`playwright-report.json` from the evidence dir to find the actual
error ("Timed out waiting 120000ms from config.webServer"). When the
underlying tool produces a clear error, surface it.

### No leverage on auth lifecycle

You sent me three fresh JWTs across the session because each was
minutes from expiring during iteration. If TraceOn read auth from a
`.traceon/auth.json` or similar (gitignored), it'd remove a recurring
papercut.

## Is it worth it overall?

For this team, yes — but conditionally:

- **Yes** for any change that crosses frontend and backend, especially
  observability-sensitive paths (preflight, headers, federation, async
  callbacks). The CORS find alone justified the setup cost.
- **Probably not** for assertion-level tests where the symptom IS the
  bug (button missing, validation wrong). Plain Playwright + a
  screenshot is faster and has less infrastructure surface.
- **Diminishing returns over time** if you fix the first-run issues
  once and bake the conventions (CORS allow `traceparent`, pnpm config
  sorted, `webServer` port correct, env forwarding sorted, auth helper).
  Once the friction is gone, the per-feature cost drops from "30 min
  of yak-shaving" to "30 seconds." That tipping point is where it
  becomes routinely worth it. You haven't reached that yet — most of
  my time today was hitting the same kind of setup pothole twice.

**If I had to pick the single highest-ROI improvement: env forwarding.**
It's blocking the obvious "inject AUTH_TOKEN cleanly" pattern, and the
workarounds (inline secrets in tests, strip before commit, hope nobody
fat-fingers a commit) are exactly the failure modes a verification
tool should be eliminating, not creating.

## Maintainer's response

Read of the feedback: accurate. None of these criticisms are wrong, and
the highest-ROI ask is the right one to pick.

| # | Drag point | Root cause | Scope | Status |
|---|---|---|---|---|
| 1 | `env` param doesn't forward | Naming collision — the schema's `env` is a SigNoz config-profile name (`'default'`/`'staging'`), not env vars. The user's `AUTH_TOKEN=…` string is silently ignored. | Rename existing `env` → `signoz_env`; add `extra_env: Record<string, string>` that gets forwarded to the Playwright subprocess. ~30 min including a vitest case. | Pending |
| 2 | First-run friction × 3 | Each blocker is environment-shape, not TraceOn bug. Pre-flight check could catch all three before the test runs. | Add `traceon doctor` subcommand or auto-preflight in `verify`: probe `<base>/healthz` from a node fetch with `traceparent` to check CORS allow-headers; warn if test uses `webServer` block with mismatched port; detect pnpm install path conflicts. ~2-3h. | Pending |
| 3 | Coverage warnings are noise | Same warning whether real miss or attribution false alarm. | Two-track signal: keep `attribution_limited` flag for the OTel gap, and add a separate "no spans at all" check for the "test never hit backend" case. Suppress the warning when test asserted on response-shape DOM. ~1-2h, judgment-heavy. | Pending |
| 4 | Timeout reports empty fields | `webServer` timeout path didn't go through file-based reader. | Extend `buildSummaryFromReport` to ALSO read `playwright-report.json` when present (even if `runPlaywright` got a non-zero exit early); fall back to parsing the last error line in stderr if neither file exists. ~30 min. | Pending — note: v0.0.5+ should already surface stdout/stderr tails for unrecognised failures; webServer timeout may bypass that. |
| 5 | Auth lifecycle | JWTs expire every few minutes during iteration. | Read from `.traceon/auth.json` (gitignored) if present; expose to the Playwright subprocess as `TRACEON_AUTH_<key>` env vars. Lets the test reference a stable name without hardcoding the token. ~45 min. | Pending |

### Recommended ship order

1. **Drag #1 (env forwarding)** first. Highest-ROI per the user. Small
   diff, eliminates the inline-JWT papercut, and unblocks #5 (auth
   helper can use the same forwarding mechanism).
2. **Drag #4 (timeout summary)** next. Small fix, fully addresses the
   "had to read raw JSON" papercut. Ships cleanly with #1.
3. **Drag #5 (auth lifecycle)** after #1 lands. Builds on the env
   forwarding to give a stable name (`TRACEON_AUTH_TOKEN`) the test
   can reference.
4. **Drag #2 (preflight check)** later, larger scope, real product
   work.
5. **Drag #3 (coverage warnings)** last, hardest to get right without
   creating new false negatives.
